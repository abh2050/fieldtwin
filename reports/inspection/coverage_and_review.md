# Coverage, evidence review, and inspection requests

Generated by `pipelines/inspection/reports.py`.

## Coverage

Each usable registry well, graded against Carbon Mapper scene footprints (cloud limit 25%, Carbon Mapper's own condition for a candidate null detect):

| Status | Wells | Meaning |
|---|---:|---|
| `PLUME_NEARBY` | 205 | A plume origin within 250 m. Proximity only. |
| `IMAGED_NO_PLUME_NEARBY` | 439 | Inside a clear scene, with no plume origin within the radius. Not a clean bill of health: nothing exceeded the detection limit at those moments. |
| `IMAGED_CLOUDY_ONLY` | 0 | Only cloudy or unknown-cloud scenes. |
| `NOT_IMAGED` | 1 | No listed scene footprint contains it. |

Wells with plumes nearby, by number of plumes: 1: 91, 2-4: 86, 5+: 28.

## Evidence cards

60 cards, one per well with a NAIP chip: CONTROL 20, NEAR_PLUME 40. Each card holds the coverage status, every plume within the radius with a proximity caption, the chip, attribution for both sources, and these fixed statements:

- Spatial proximity is not source attribution.
- The registry lists gas wells only. Other infrastructure nearby is not represented.
- Plume origins are estimates and may not match infrastructure locations exactly.
- Aerial imagery provides context only. It carries no labels for emissions or equipment condition.
- Absence of a plume means only that nothing exceeded the instrument's detection limit when imaged.
- These are real public records. None of them describes AETHER Field, which is fictional.

Every sentence on a card passes a claim guard (`packages/inspection/claims.py`) that rejects leak, cause, attribution, defect, certainty, drone, and AETHER claims unless negated. The rendered pages are checked again line by line. Pages are written to `data/gold/inspection/`, which is not committed, because they show real wells beside real plume records.

## Human review

Review is blinded: the queue shows each chip by an opaque ID, with nothing about plumes, so the reading of an image isn't steered by whether a plume was detected nearby. Outcomes are limited to `NO_FEATURE_OF_NOTE`, `INFRASTRUCTURE_VISIBLE`, `IMAGE_UNUSABLE`, `FIELD_VERIFICATION_SUGGESTED`. None confirms a leak or names a source. Reviews are append-only; a correction supersedes, and the database enforces both.

**Reviews recorded: 0** (0 items with a current finding; NO_FEATURE_OF_NOTE 0, INFRASTRUCTURE_VISIBLE 0, IMAGE_UNUSABLE 0, FIELD_VERIFICATION_SUGGESTED 0). The workflow is built and tested, but no human has reviewed these images yet, and none were invented.

## Inspection requests

1 request(s), for fictional assets A-03, generated from the stored AETHER-FAULT-001 prioritization input. Requests come only from synthetic AETHER events and can target only fictional assets; the database refuses a real well or a benchmark event. They carry no priority score, which is Gate 7's job. No request is ever generated for a real well.
